# Capa própria do reel — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a video of a TryPost post can carry an own cover image (`meta.cover_url`), set in the composer's Capa tab or through the API/MCP, and Instagram reels are created with it.

**Architecture:** a patch on upstream `trypostit/trypost` v2.0.0 (`patches/reel-cover-image.patch`), applied by the fork's build workflow. The cover is a JPEG in `covers/<uuid>.jpg` on the default disk, outside the `media` table and its 24 h prune; its public URL lives in the video item's `meta.cover_url`, next to the existing `cover_offset_ms`.

**Tech Stack:** Laravel 13 / PHP 8.4, Pest 5, intervention/image 4 (GD), Vue 3 + Inertia + Wayfinder, GitHub Actions, EasyPanel.

**Spec:** `docs/superpowers/specs/2026-11-16-capa-reel-design.md`

## Global Constraints

- Work in an upstream checkout at tag `v2.0.0`; never edit the upstream repo itself. The patch is `git diff v2.0.0` of that checkout.
- Cover file: JPEG, sRGB, longest side within 1080×1920 (scale down, never crop, never upscale), ≤ 8 MB, path `covers/<uuid>.jpg` on the default disk.
- `cover_url` accepted only when it starts with `Storage::url('covers/')`.
- Instagram reel container: send `cover_url` when set, and keep sending `thumb_offset` as today.
- New translation keys in all 16 `lang/*/posts.php` (pt-BR and en translated, the other 14 in English).
- Gated steps (ask the user, then do): the Meta probe (Task 0), installing tools on the Mac (Task 1), push/build/deploy (Task 6), the acceptance post (Task 7). Never publish a post only to test.
- Times near scheduled posts are off limits for the deploy (read `list-posts-tool` status scheduled first).

## Review Focus

- A `cover_url` from another host (or a path outside `covers/`) → refused with the translated message, not stored (Task 2 test).
- A PNG or WebP cover, or one bigger than 1080×1920 → stored as a JPEG within the bounds (Task 3 test).
- "Remover" in the Capa tab → `meta.cover_url` gone from the item on save, `cover_offset_ms` kept (Task 4 check).
- A duplicated post → its video keeps the same `cover_url` (Task 2 test through `SyncOwnedMedia`).
- A reel without `cover_url` → the container params are exactly today's (Task 2 test).
